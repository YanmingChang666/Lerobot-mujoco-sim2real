## 最常用：X02 居中并顺时针旋转 90°

```bash
python -m X02.write --text 永 \
  --center 0.20 0 \
  --height -0.10 \
  --pen-yaw-deg 90 \
  --rotation-deg -90 \
  --hold
```

一行复制版：

```bash
python -m X02.write --text 永 --center 0.20 0 --height -0.10 --pen-yaw-deg 90 --hold --rotation-deg -90
```

- `Y=0` 将纸面放到机器人左右中线；`X=0.20` 为基座前方 20 cm。
- `Z=-0.10` 相对模型基座坐标系，不是相对现实地板。
- `--pen-yaw-deg 90` 调整笔的水平朝向以适应关节范围，笔尖仍竖直向下。
- `--rotation-deg -90` 旋转汉字；从世界 +Z 俯视纸面，负角度为顺时针。
- GUI 初始显示 1 秒，再从七关节零位平滑进场 5 秒；完成后保持窗口。

这组完整参数已用基线验证“永”字 2354 个轨迹点：RMSE 0.0252 mm，最大误差 0.1144 mm。
结果在 `X02/outputs/centered_rotated/`。这是无接触仿真跟踪结果。

## 英文单词书写

新的 `PIPER.write`、`WheelArmR.write`、`X02.write` 自动识别英文，无需汉字 JSON。
目前支持 A–Z、a–z 与普通空格，采用单线大写字母；`Hello` 显示为 `HELLO`。
不支持真正的小写字形、花体连笔、数字、标点或中英文混排。

```bash
# X02：居中，英文单词顺时针旋转 90 度
python -m X02.write --text Hello --center .20 0 --height -.10 \
  --pen-yaw-deg 90 --rotation-deg -90 --size .08 --hold

# 多个单词需要引号；整段文字缩放到同一字框内，字越多单个字母越小
python -m X02.write --text "HELLO WORLD" --center .20 0 --height -.10 \
  --pen-yaw-deg 90 --rotation-deg -90 --size .08 --hold

# 另外两种机械臂使用各自默认工作区
python -m PIPER.write --text HELLO --size .08 --hold
python -m WheelArmR.write --text HELLO --size .08 --hold
```

英文 `--size .08` 表示整个单词/短语等比例放入 8 cm × 8 cm 框内；
汉字仍表示单字尺寸。尺寸是在旋转前定义的，任意角度旋转后仍需检查可达性。
默认继续使用 5 秒进场、抬落笔与红绿轨迹；长短语即使尺寸缩小也会因抬笔次数增加而更耗时。

要运行英语任务 MPC，先用相同单词、位置和旋转参数执行 `--mode plan`，再独立训练。
例如 X02 当前配置：

```bash
python -m X02.write --mode plan --text HELLO --center .20 0 --height -.10 \
  --pen-yaw-deg 90 --rotation-deg -90 --size .08 --headless
python train.py --env X02Writing --model DBKN --mode train --suffix x02_hello \
  --train_samples 1500 --train_steps 30 --test_samples 32 --test_steps 60 \
  --num_epochs 100 --eval_interval 10 --batch_size 128 --eval_batch_size 128 --device cpu
python -m X02.write --text HELLO --center .20 0 --height -.10 \
  --pen-yaw-deg 90 --rotation-deg -90 --size .08 --mode mpc --hold \
  --checkpoint results/X02Writing/x02_hello/DBKN/best_model.pt
```

以上是重新训练命令，不代表已生成 `x02_hello` 权重。已有汉字权重不等于已验证的英文模型。
英文笔画定义在 `control/latin_strokes.py`，公共规划入口在 `PIPER/trajectory.py`。
旧 SO-ARM101 `write_demo.py` 仍使用汉字加载器，本次未给它增加英文接口。

已验证 X02 居中旋转 `Hello` 基线：2981 个采样点完整执行，RMSE 0.0217 mm，最大误差 0.0805 mm。
结果位于 `X02/outputs/english/Hello_baseline.*`，为无接触仿真结果。

## X02 右臂

保留躯干和左臂外观，左臂固定，仅控制右臂 `joint1_r` 至 `joint7_r`。

```bash
# 默认右侧位置
python -m X02.write --text 永 --hold

# 右侧位置，字顺时针旋转 90°
python -m X02.write --text 永 --rotation-deg -90 --hold

# 中间位置，字保持原方向
python -m X02.write --text 永 --center .20 0 --height -.10 --pen-yaw-deg 90 --hold

# 中间位置，字顺时针旋转 90°
python -m X02.write --text 永 --center .20 0 --height -.10 --pen-yaw-deg 90 --rotation-deg -90 --hold

# 中间位置，仅检查进场；使用旋转后的第一笔作为进场目标
python -m X02.write --text 永 --center .20 0 --height -.10 \
  --pen-yaw-deg 90 --rotation-deg -90 --approach-only --hold

# 默认右侧位置的已训练 MPC
python -m X02.write --text 永 --mode mpc --hold \
  --checkpoint results/X02Writing/x02_write_demo/DBKN/best_model.pt
```

`x02_write_demo` 是右侧工作区权重，中间位置应重新规划并训练。
不能只把右侧配置的 `Y` 改成 0 就假定整条轨迹可达；使用已验证的中心、高度和笔姿态组合。
详细说明：[X02/README_CN.md](../X02/README_CN.md)。

## x02cTpose 四关节右臂

这是另一套 T-pose URDF，右臂只有 4 个活动关节、腕部固定。
使用位置优先和软倾角约束，**不保证笔尖竖直**；默认书写会产生约十几度倾角。
保留全身外观，其余关节固定，不执行站立平衡控制。

```bash
python -m x02cTpose.write --text 永 --hold
python -m x02cTpose.write --text 永 --rotation-deg -90 --hold
python -m x02cTpose.write --text HELLO --rotation-deg -90 --hold
python -m x02cTpose.write --text 二 --approach-only --home-deg 0 0 0 0 --hold
python -m x02cTpose.write --text 永 --mode mpc --hold \
  --checkpoint results/X02CTPoseWriting/tpose_write_demo/DBKN/best_model.pt
```

默认纸面 `(0.30,-0.20,0.90)` m，进场 5 秒。不支持非零 `--pen-yaw-deg`，
不要复制七轴 X02 的居中命令。英文和汉字使用相同文字生成器；每组新参数仍需验证可达性。
该模块也支持后述的 size、lift、speed、headless、output、snapshot 等通用选项，
但 home-deg 只接收 4 个角度，笔姿态约束与前述三种模型不同。
完整生成、训练命令及模型限制见 [x02cTpose/README_CN.md](../x02cTpose/README_CN.md)。

## 通用参数、启动和结果

**本节仅适用于 `PIPER.write`、`WheelArmR.write`、`X02.write`。**

| 参数 | 用途 / 单位 |
|---|---|
| `--text 永` | 指定汉字；多字会增加占用空间，需重新检查可达性 |
| `--mode baseline` | 默认，关节速度前馈 + 位置误差反馈 |
| `--mode plan` | 只规划，保存用于采样训练的参考轨迹，不执行书写 |
| `--mode mpc --checkpoint 路径` | 用匹配该机器人的 DBKN 权重进行 MPC 控制 |
| `--size .08` | m；汉字单字尺寸，英文整段文字包围框尺寸 |
| `--center X Y` | 文字布局中心，世界/模型基座坐标，m |
| `--height Z` | 落笔平面高度，m |
| `--lift .03` | 相对落笔平面的抬笔高度，m |
| `--speed .025` | 笛卡尔分段峰值速度，m/s；过大可能触发关节速度检查 |
| `--rotation-deg -90` | 绕文字布局中心旋转字和纸面，不改变笔尖朝下约束 |
| `--pen-yaw-deg 90` | 改变笔的水平姿态，不旋转字；可能改变可达工作区 |
| `--home-deg ...` | 初始关节角，度；Piper 6 个，另两种机械臂 7 个 |
| `--approach-seconds 5` | 进场时长，默认 5 s，须满足速度约束且为 0.02 s 的整数倍 |
| `--approach-only` | 到第一笔上方后停止，不落笔 |
| `--start-hold 1` | GUI 中运动前展示初始姿态的时间，s |
| `--hold` | 书写结束后保持 GUI，关闭窗口退出 |
| `--headless` | 无 GUI，加速仿真；5 s 指仿真时间，不是墙钟时间 |
| `--snapshot 路径.png` | 保存包含机器人和红绿路径的三维截图 |
| `--output 目录` | 输出目录，默认各机器人目录下的 `outputs/` |
| `--hanzi-data 目录` | 笔画 JSON 所在目录 |

参数帮助：`python -m X02.write --help`，另两个模块同理。
默认笔画库为仓库同级的 `hanzi-writer-data/data/`。

**无窗口检查与截图：**

```bash
MUJOCO_GL=egl python -m X02.write --text 永 \
  --center .20 0 --height -.10 --pen-yaw-deg 90 --rotation-deg -90 \
  --headless --output X02/outputs/centered_rotated \
  --snapshot X02/outputs/centered_rotated/scene.png
```

替换模块名和对应位置参数，可用于其他新入口。
`MUJOCO_GL=egl` 建议仅放在无窗口命令前；GUI 命令需要有效图形显示环境。

**输出文件：**

| 文件 | 内容 |
|---|---|
| `<字>_approach.json` | 进场是否完成、仿真/实际时长、到达关节误差与速度 |
| `<字>_approach.npz` | 启动参考/实际状态、时间、动作、关节名称 |
| `<字>_baseline.json` / `<字>_mpc.json` | 完成标志、RMSE、最大位置误差、倾角、旋转参数 |
| 同名 `.npz` | 参考与实际笔尖位置、参考关节角、落笔标记、动作 |
| 同名 `.png` | 实际落笔轨迹对照与误差曲线 |

红色为参考路径，绿色为实际笔尖路径；浅色为抬笔/转移/进场。
同一个字和模式在同一目录再次运行会覆盖同名结果。对比位置或旋转方案时使用不同 `--output`。
`completed=true` 只表示执行完整，还应查看 `max_error_mm` 和 `tracking_pass_2mm`。

## 重新训练 DBKN

流程：**同一套位置/旋转参数规划 → 采样与训练 → 用相同参数运行 MPC**。
下面命令均使用已有环境变量 `OPENBLAS_NUM_THREADS=1`、`OMP_NUM_THREADS=1`。
重复使用同一个 suffix 会更新该目录权重；保留旧实验时换新 suffix。

```bash
  --num_epochs 100 --eval_interval 10 --batch_size 128 --eval_batch_size 128 --device cpu
python -m PIPER.write --text 永 --mode mpc --hold \
  --checkpoint results/PIPER/piper_custom/DBKN/best_model.pt
```

### X02 居中且顺时针旋转 90°

此组合已验证基线；下面是重新训练并验证其 MPC 的操作命令，不代表本教程编写时已生成该 suffix 的权重。

```bash
python -m X02.write --mode plan --text 永 \
  --center .20 0 --height -.10 --pen-yaw-deg 90 --rotation-deg -90 --headless
python train.py --env X02Writing --model DBKN --mode train --suffix x02_center_rot90 \
  --train_samples 1500 --train_steps 30 --test_samples 32 --test_steps 60 \
  --num_epochs 100 --eval_interval 10 --batch_size 128 --eval_batch_size 128 --device cpu
python -m X02.write --text 永 \
  --center .20 0 --height -.10 --pen-yaw-deg 90 --rotation-deg -90 \
  --mode mpc --hold \
  --checkpoint results/X02Writing/x02_center_rot90/DBKN/best_model.pt
```

每种机器人只有一个当前训练参考文件；再次 `--mode plan` 会覆盖它，`--output` 不改变该参考路径。
Piper 为 `PIPER/data/reference.npz`，另两种为各自 `data/writing_reference.npz`。
新训练从当前参考周围采样。标准书写 DBKN 不启用 `--u_z`、`--use_stable`。
加载权重会检查维度、XML 哈希、周期及关节采样覆盖；通过覆盖检查也不等于对新任务精度作保证。
不要把不同机械臂的 `best_model.pt` 混用；同时保留其同目录的机器人数据元信息 JSON。

## SO-ARM101 旧书写流程

当前 `write_demo.py` 依赖真机状态桥接，启动时调用 `sync_real_to_sim_start()`；
它会发布控制指令，不能作为前述三个纯仿真入口直接替换运行。
本次教程整理未启动真机、未重新验证硬件链路。

**先修改字与轨迹配置：**

- `write_demo.py` 中 `CHAR = "二"` 改成目标单字。
- 当前字框在 `hanzi_to_strokes(CHAR, size_m=0.12)` 设置。
- 两处 `generate_multi_stroke()` 的 `center`、`write_height`、`lift_height` 必须同步修改。
- 当前 `center=(0.35,0)`、`write_height=0.025`、`lift_height=0.12`。
- 旧 `lift_height` 是绝对世界 Z；新入口的 `--lift` 是相对纸面的高度，两者不同。
- 旧入口不支持本教程的 `--text`、`--center`、`--rotation-deg`、`--pen-yaw-deg`、`--hold`。
  旧代码固定 `wrist_roll` 的 -90° 调整是握笔姿态，不是把汉字旋转 -90°。

**已配置并标定硬件时，使用两个终端：**

```bash
# 终端 1：真实 SO-ARM101 驱动，将访问硬件
conda activate lerobot-env
cd /home/cym/ROS/Arms/isaac_so_arm101/Lerobot-mujoco-sim2real/lerobot_sim2real
python so101_real.py
```

```bash
# 终端 2：仿真 + MPC + 书写，向上述驱动发送目标角度
conda activate koopman-sim2real
cd /home/cym/ROS/Arms/isaac_so_arm101/Lerobot-mujoco-sim2real
python write_demo.py --env SOARM101 --model DBKN --suffix wide_range
```

读取 `results/SOARM101/wide_range/DBKN/best_model.pt`。无真机状态发布时，旧脚本会等待并超时报错。
若要自行训练 SO-ARM101 DBKN：

```bash
python train.py --env SOARM101 --model DBKN --mode train --suffix so101_custom
```

随后将书写命令的 suffix 改成 `so101_custom`，并核对训练关节范围与笔画参考。
SO-ARM101 使用原采样器，不能通过 `X02.write --mode plan` 等命令改变它的训练工作区。
硬件环境、串口、标定及桥接说明见 [主 README](../README_CN.md#-部署到真实机械臂)。

## 常见问题与验证

| 提示 / 现象 | 处理 |
|---|---|
| `Unreachable ... pose` | 调整中心、高度、字框或笔姿态；先恢复该机器人已验证参数，不放宽真实关节范围 |
| `Reference requires ... rad/s` | 减小 `--speed`；程序不会静默压缩轨迹导致失真 |
| `Approach needs ... rad/s` | 增加 `--approach-seconds`，或调整初始角度 |
| `Approach did not settle` | 检查模型与伺服参数、到达误差和速度；不能忽略检查继续落笔 |
| `Writing trajectory exceeds training joint coverage` | 按当前全部轨迹参数重新 plan、采样、训练 |
| `Model/timestep differs from training` | 模型/周期改变后重新 plan 和训练 |
| checkpoint 或元信息不存在 | 完成对应训练，或选择已存在的完整权重目录 |
| 找不到笔画 JSON | 指定 `--hanzi-data /实际路径/hanzi-writer-data/data` |
| GUI 无法打开 | 使用有图形显示的终端；只需计算时用 `--headless` |
| 运行完窗口关闭 | 添加 `--hold`；该参数对无窗口模式无效 |
| 多次结果混在一起 | 为每个方案设置独立 `--output` |
