## 一、支持的机器人

| # | 机器人（`--robot`） | 书写关节 | 笔姿态 | 需先生成模型 | 自带 MPC 权重 |
|---|---|---|---|---|---|
| 1 | `piper`：AgileX Piper 六轴臂 | 6 | 笔尖竖直 | 否 | 有（按"永"训练） |
| 2 | `wheelarm_r`：WheelArm 单独右臂 | 7 | 笔尖竖直 | 否 | 有（按"永"训练） |
| 3 | `x02`：X02 人形上身右臂 | 7 | 笔尖竖直 | 否 | 有（按"永"训练） |
| 4 | `x02c_tpose`：x02c T-pose 人形右臂 | 4 | 只跟踪位置，笔会倾斜十几度 | 否 | 有（按"永"训练） |
| 5 | `g1_right`：Unitree G1 人形右臂 | 7 | 笔尖竖直 | 是 | 无 |
| 6 | `so101`：SO-ARM101（新框架） | 5 | 笔竖直，绕笔转角自由 | 是 | 无 |
| 7 | `wheel_robot_r`：轮式机器人**整机**，右臂书写 | 7 | 笔尖竖直 | 是 | 无 |
| 8 | `robot0309_r`：robot0309 **整机**，右臂书写 | 6 | 笔尖竖直 | 是 | 无 |
| 9 | SO-ARM101 旧真机流程（`write_demo.py`） | 5 | 只锁定腕部转角 | 否 | 有（`wide_range`） |

- 1–8 号统一用 `python -m writing --robot <名字>` 运行，参数完全相同。
- 1–4 号的旧入口也照常可用，效果相同：`python -m PIPER.write`、`python -m WheelArmR.write`、
  `python -m X02.write`、`python -m x02cTpose.write`。
- 7、8 号使用整机模型：只有右臂运动；底盘、升降、腰、头和左臂固定在 URDF 零位，显示在画面中。
  `wheelarm_r` 是只有右臂的旧模型，与 `wheel_robot_r` 互不影响。
- 9 号要连接真实 SO-ARM101，与 1–8 号的纯仿真流程不同。

## 二、演示前准备

**每次打开终端执行：**

```bash
conda activate koopman-sim2real
cd ~/ROS/Arms/isaac_so_arm101/Lerobot-mujoco-sim2real
git checkout generic-writing
git pull
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1

python -m writing --list        # 列出全部机器人，确认 8 台都在
```

**第一次使用前生成模型（之后不用再跑；更新代码或改 YAML 的 `build:` 后要重新生成）：**

```bash
python -m writing.build_model --robot g1_right
python -m writing.build_model --robot so101
python -m writing.build_model --robot wheel_robot_r
python -m writing.build_model --robot robot0309_r     # 约 1 分钟，底座网格要自动简化
```

**G1 需要先确认 URDF 路径。** `robots/g1_right.yaml` 里 `build.urdf` 默认指向
`../PACE/Beyondmimic_Deploy_G1/unitree_description/urdf/g1/main.urdf`。路径不对时：

```bash
find ~ -path "*unitree_description/urdf/g1/main.urdf" 2>/dev/null
sed -i 's#^  urdf: .*#  urdf: /找到的路径/unitree_description/urdf/g1/main.urdf#' robots/g1_right.yaml
```

**检查清单：**

- [ ] 在有图形界面的电脑上运行（远程服务器无显示器时只能用 `--headless`）
- [ ] 笔画数据完整：`ls -l ../hanzi-writer-data/data/永.json` 的大小不是 0
- [ ] 5–8 号机器人已生成模型
- [ ] 同时开多个窗口时内存足够（G1、robot0309 模型较大）

## 三、演示命令

以下命令都会打开 MuJoCo 窗口：先停留 1 秒，再进场到第一笔上方，然后落笔书写。
`--hold` 让窗口在写完后保持打开，关闭窗口即退出。

窗口中**红色**为参考轨迹，**绿色**为实际笔尖轨迹，浅色部分为抬笔、转移和进场。

### 1. 写汉字（baseline 控制，不需要训练）

```bash
python -m writing --robot piper         --text 二 --hold
python -m writing --robot wheelarm_r    --text 二 --hold
python -m writing --robot x02           --text 二 --hold
python -m writing --robot x02c_tpose    --text 二 --hold
python -m writing --robot g1_right      --text 二 --hold
python -m writing --robot so101         --text 二 --hold
python -m writing --robot wheel_robot_r --text 二 --hold
python -m writing --robot robot0309_r   --text 二 --hold
```

### 2. 写英文（A–Z，小写按大写写）

```bash
python -m writing --robot x02         --text HELLO --hold
python -m writing --robot g1_right    --text HELLO --hold
python -m writing --robot robot0309_r --text HELLO --hold
```

### 3. 旋转字（负角度为顺时针）

```bash
python -m writing --robot piper --text 二 --rotation-deg -90 --hold
```

`g1_right` 和 `so101` 默认已旋转 -90°（从机器人方向看字是正的）。要和其他机器人保持同一朝向时，
加 `--rotation-deg 0`。

### 4. X02 把纸放在正中间，并顺时针旋转 90°

```bash
python -m writing --robot x02 --text 二 --center .20 0 --height -.10 \
  --pen-yaw-deg 90 --rotation-deg -90 --hold
```

### 5. 只演示进场，不落笔

```bash
python -m writing --robot g1_right    --text 二 --approach-only --hold
python -m writing --robot robot0309_r --text 二 --approach-only --hold   # 进场 6 秒
```

### 6. 学习模型 + MPC 控制（仓库自带权重，按"永"训练）

```bash
python -m writing --robot piper      --text 永 --mode mpc --hold \
  --checkpoint results/PIPER/piper_gripper_demo/DBKN/best_model.pt
python -m writing --robot wheelarm_r --text 永 --mode mpc --hold \
  --checkpoint results/WheelArmRWriting/wheelarm_write_demo/DBKN/best_model.pt
python -m writing --robot x02        --text 永 --mode mpc --hold \
  --checkpoint results/X02Writing/x02_write_demo/DBKN/best_model.pt
python -m writing --robot x02c_tpose --text 永 --mode mpc --hold \
  --checkpoint results/X02CTPoseWriting/tpose_write_demo/DBKN/best_model.pt
```

权重只覆盖训练时的字和纸面位置；换字或换位置会报“超出训练范围”，需要按第四节重新训练。

### 7. 多台机器人同时写同一个字

每台机器人一个窗口，窗口出现后手动拖开排列：

```bash
for r in piper x02 g1_right wheel_robot_r robot0309_r; do
  python -m writing --robot $r --text 二 --rotation-deg 0 --hold \
    --output compare_outputs/二/$r &
done
wait
```

- 各台机器人规划耗时不同（几秒到一分钟），窗口出现时间不同，**开始运动不同步**。
- 红绿轨迹、视角方向、纸张大小、进场后的书写速度一致。镜头远近、纸面位置、灯光、地面按各自模型设置。
- `x02c_tpose` 的笔会倾斜，这是它只有 4 个关节造成的。

### 8. SO-ARM101 真机（旧流程，需连接硬件）

```bash
# 终端 1：真机驱动
conda activate lerobot-env
cd ~/ROS/Arms/isaac_so_arm101/Lerobot-mujoco-sim2real/lerobot_sim2real
python so101_real.py

# 终端 2：仿真 + MPC，向真机发送目标角度
conda activate koopman-sim2real
cd ~/ROS/Arms/isaac_so_arm101/Lerobot-mujoco-sim2real
python write_demo.py --env SOARM101 --model DBKN --suffix wide_range
```

真机标定、`joint_offsets` 和安全须知见 [主 README](../README_CN.md#-部署到真实机械臂)。
上真机前确认周围无障碍物，全程有人看护，异常时 Ctrl+C。

## 四、为新机器人训练 MPC

5–8 号机器人没有自带权重。流程是“用相同参数规划 → 训练 → 用相同参数运行 MPC”。
训练用的 `--env` 名称：

| 机器人 | `--env` |
|---|---|
| `g1_right` | `G1RightWriting` |
| `so101` | `SO101Writing` |
| `wheel_robot_r` | `WheelRobotRWriting` |
| `robot0309_r` | `Robot0309RWriting` |

以 robot0309 为例：

```bash
# 1. 规划参考轨迹（字、位置、旋转要和最后演示时完全一致）
python -m writing --robot robot0309_r --mode plan --text 二 --headless

# 2. 训练 DBKN（CPU 即可；内存较小时减小 --train_samples）
python train.py --env Robot0309RWriting --model DBKN --mode train --suffix r0309_demo \
  --train_samples 1500 --train_steps 30 --test_samples 32 --test_steps 60 \
  --num_epochs 100 --eval_interval 10 --batch_size 128 --eval_batch_size 128 --device cpu

# 3. 用 MPC 书写
python -m writing --robot robot0309_r --text 二 --mode mpc --hold \
  --checkpoint results/Robot0309RWriting/r0309_demo/DBKN/best_model.pt
```

- 每台机器人只保存一份当前参考轨迹。再次运行 `--mode plan` 会覆盖它。
- 不同机器人的权重不能混用。权重目录里的元信息 JSON 要和 `best_model.pt` 放在一起。

## 五、常用参数

| 参数 | 作用 |
|---|---|
| `--text 二` | 汉字或英文（中英文不能混写） |
| `--size .08` | 字的尺寸（m）：汉字为单字大小，英文为整段文字的外框 |
| `--center X Y` / `--height Z` | 纸面中心与高度（m，世界坐标）；默认值按机器人工作区设定 |
| `--rotation-deg` | 旋转字，负值为顺时针 |
| `--pen-yaw-deg` | 笔绕竖直轴转角，只有 6 轴及以上的机器人支持 |
| `--lift .03` / `--speed .025` | 抬笔高度（m）/ 书写速度（m/s） |
| `--approach-seconds` | 进场时长（默认 5 s，robot0309 为 6 s） |
| `--approach-only` | 只进场，不落笔 |
| `--mode baseline / mpc / plan` | 控制方式；`plan` 只生成训练参考 |
| `--hold` / `--headless` | 写完保持窗口 / 不开窗口 |
| `--snapshot 路径.png` | 保存三维截图 |
| `--output 目录` | 结果目录 |
| `--home-deg ...` | 初始关节角（度），个数等于书写关节数 |

完整参数：`python -m writing --robot <名字> --help`。

## 六、结果文件

| 机器人 | 默认结果目录 |
|---|---|
| `piper` / `wheelarm_r` / `x02` / `x02c_tpose` | `PIPER/outputs/`、`WheelArmR/outputs/`、`X02/outputs/`、`x02cTpose/outputs/` |
| 其余新机器人 | `robots/<名字>/outputs/` |

每次运行会生成以下文件；同一个字、同一种模式再次运行会覆盖同名文件：

| 文件 | 内容 |
|---|---|
| `<字>_approach.json/.npz` | 进场是否完成、到达误差 |
| `<字>_<模式>.json` | 是否完成、平均误差 `rmse_mm`、最大误差 `max_error_mm`、笔倾斜 `max_pen_tilt_deg` |
| `<字>_<模式>.png` | 轨迹对照图与误差曲线 |
| `<字>_<模式>.npz` | 参考与实际笔尖轨迹、关节角、控制量 |

`completed: true` 只表示执行完了。精度看 `max_error_mm` 和 `tracking_pass_2mm`。

**已验证的仿真结果（写"二"，baseline）：**

| 机器人 | 最大误差 | 笔倾斜 |
|---|---|---|
| `g1_right` | 0.07 mm | < 0.01° |
| `so101` | 0.04 mm | < 0.01° |
| `wheel_robot_r` | 0.13 mm | 0.02° |
| `robot0309_r` | 1.38 mm（出现在落笔前的抬笔段；落笔后 < 0.5 mm） | 0.07° |

## 七、常见问题

| 现象 | 原因与处理 |
|---|---|
| `汉字 'X' 的笔画数据文件是空的` | 该字的笔画数据为 0 字节，重新下载 hanzi-writer-data，或换一个字 |
| `找不到汉字 'X' 的笔画数据` | 字不在数据集中，或用 `--hanzi-data /路径/hanzi-writer-data/data` 指定目录 |
| `model ... does not exist; build it first` | 先运行 `python -m writing.build_model --robot <名字>` |
| G1 生成模型时 `No such file or directory ... main.urdf` | 按第二节修改 `robots/g1_right.yaml` 的 `build.urdf` |
| `Unreachable ...` / `No start pose gives a feasible whole path` | 纸面超出手臂工作区：调整 `--center`、`--height`，或缩小 `--size` |
| `Reference requires ... rad/s` | 书写太快，减小 `--speed` |
| `Approach needs ... rad/s` | 进场距离太远，增大 `--approach-seconds`（报错会给出最小值） |
| `Approach did not settle` | 手臂太重、跟随太慢：在 YAML 的 `build:` 中加大 `kv`（robot0309 用 800），重新生成模型 |
| `Writing trajectory exceeds training joint coverage` | MPC 权重不覆盖当前字/位置，按第四节重新规划和训练 |
| robot0309 看不到夹爪 | 夹爪网格包 `Servogripper1010` 不在仓库中，放到 `robot0309` 旁边后重新生成模型 |
| 窗口打不开 | 需要图形桌面；只计算结果时用 `--headless` |
| 运行完窗口自动关闭 | 加 `--hold` |
| 第一次运行某台机器人较慢 | 正在自动搜索 IK 起始姿态；把打印出的 `- [...]` 复制到 YAML 的 `ik.seeds` 下，下次跳过搜索 |

## 八、能力边界

- 只在水平纸面上书写，文字只绕竖直轴旋转；不支持白板等竖直平面。
- 基座固定、理想重力补偿；人形机器人站立平衡不在本流程中。
- 笔刚性固定在手上；不模拟手指抓握，也不模拟纸面接触和压力。
- 1–8 号只在仿真中验证。仿真误差不等于真机书写精度。
- `robot0309_r` 使用的 `rr51` 关节位于模型 +Y 一侧。按 ROS 习惯（x 朝前）这是左侧，请确认是否就是要用的右臂；
  如需换另一侧，把 YAML 中的 `joints` 改为 `lr52_1_joint`–`lr52_6_joint`，纸面 Y 改为负值。
