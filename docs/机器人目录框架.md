# 机器人目录框架

书写相关资源统一落在 `robots/`。`--robot <名字>` 与 `robots/<名字>.yaml`、`robots/<名字>/` 一一对应。

## 三层结构

```text
仓库根目录/
├── writing/              # 统一入口：python -m writing --robot <名字>
├── robots/               # ★ 配置 + 模型（按机器人名）
│   ├── <名字>.yaml       # 书写 / 训练配置
│   └── <名字>/           # 该机源模型、书写 MJCF、输出
│       ├── source/       # 原始 URDF / 网格（可选）
│       ├── assets/       # 书写用 MJCF（*.xml）
│       ├── data/         # 训练参考 / 缓存（运行时）
│       └── outputs/      # 轨迹、截图、录像（运行时）
├── PIPER/ WheelArmR/ X02/ x02cTpose/ SOARM101/
│                         # 旧实现 Python 包；YAML overrides 仍引用它们
├── train.py / models/ / control/
│                         # 通用 DBKN / MPC，与具体机型无关
└── robot0309/  unitree_description/
                          # 根目录遗留拷贝，勿当正式源；正式源在 robots/*/source/
```

命令入口：

```bash
python -m writing --list
python -m writing --robot <名字> --text 二 --hold
```

## 单机目录约定

```text
robots/<名字>/
├── source/          # 原始 URDF + meshes（build.urdf 指向这里）
├── assets/          # <名字>_write.xml（YAML 的 model:）
├── data/            # reference.npz、训练缓存（可不入库）
└── outputs/         # 书写结果 / mp4（可不入库）
```

- 有 `overrides:` 的机型（piper / wheelarm_r / x02 / x02c_tpose）复用根目录旧包里的 Env / planner / 数据采集。
- 无 `overrides:` 的机型走 `writing` 通用实现，模型与数据都在 `robots/<名字>/`。
